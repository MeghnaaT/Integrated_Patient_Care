# Integrated Patient Care Management System (IPCMS)

## Overview
A modern, role‑based **Flask** web application for managing patients, doctors, nurses, appointments, and medical records.  
It follows the **Application Factory** pattern, uses **SQLAlchemy** ORM, **Flask‑Login** for authentication, and **Flask‑WTF** for server‑side form validation.  
The UI is built with **Bootstrap 5** and a custom design system (glass‑morphism, gradients, premium components).

---

## Quick Start
1. **Clone / copy the repository** and `cd` into the project root (`e:/meghna/Integrated_Patient_Care`).
2. **Create a virtual environment** (recommended) and install dependencies:
   ```bash
   python -m venv .venv
   .venv\Scripts\activate   # Windows PowerShell
   pip install -r requirements.txt
   ```
3. **Configure environment variables**:
   - Copy the template:
     ```bash
     copy .env.example .env
     ```
   - Edit `.env` and fill in your MySQL credentials, a strong `SECRET_KEY`, and the desired `FLASK_ENV` (`development` or `production`).
4. **Initialize the database** (creates tables & seed data):
   ```bash
   .venv\Scripts\python setup_database.py
   ```
5. **Run the development server**:
   ```bash
   python run.py
   ```
   The app will be reachable at <http://127.0.0.1:5000>.

## Development Tips
* **Hot‑reload** – Flask’s built‑in reloader works out‑of‑the‑box in development mode (`FLASK_ENV=development`).
* **Database migrations** – For future schema changes, integrate **Flask‑Migrate** (`alembic`).
* **Testing** – The project is ready for `pytest` – create a `tests/` package and use the `create_app('testing')` config.
* **Static assets** – All custom CSS/JS live under `static/`.  
  The design system (`styles.css`) implements the premium look‑and‑feel specified in the brief (glass‑morphism, gradients, subtle hover animations).

## Security Checklist
* **Never commit** real `.env` values – `.gitignore` excludes `.env`.
* **Password hashing** – `werkzeug.security.generate_password_hash(..., method='scrypt')`.
* **CSRF protection** – enabled globally via `Flask‑WTF` (`CSRFProtect`).
* **Session cookies** – `SESSION_COOKIE_HTTPONLY` and `SESSION_COOKIE_SAMESITE` enforced; HTTPS‑only in production.
* **Role‑based access** – `utils.decorators.role_required` aborts with HTTP 403 for unauthorized access.
